# 验收后安全修复与运营完善

本说明针对 Windows、PowerShell 7 与现有 StayOS Compose 环境；2026-10-31 第五批未过滤完整回归及前后端构建通过，V1.0 本地收口完成。同批证据及此前失败、中断记录见 [V1-CLOSURE.md](V1-CLOSURE.md)，真实上线状态以 [发布清单](V1-RELEASE-CHECKLIST.md) 为准。原 V1.0 基线为 V12；V1.1 已增量应用 V13 并完成本地验收，详见后文边界及 V1.1 交付记录。V1.2 已完成 V14 住客笔误更正的本地验收，规则与证据见 [交付记录](releases/V1.2-DELIVERY.md)。误退房恢复仍另定规则；目前没有离机备份目录，不安装常驻备份任务、不更换现有数据库账号或密钥、不自动提交 Git。以下命令仅为操作示例，本次文档修正不执行。

## 1. 页面与岗位

- `/manage/accounts`：仅系统管理员可用。新增员工、按账号或姓名查询、分页、调整固定角色、禁用/启用、重置密码。没有固定初始密码，页面关闭清空密码。最后一名启用的管理员仍受服务端保护。
- `/operations`：前台查看超预计退房和严重异常；主管查看清洁滞留、失去有效负责人的任务、未分配数量和严重异常；总经理合并两类能力；服务员仅本人任务和本人上报的严重异常。ADMIN 不自动获得该页面或酒店业务权限。
- 页面顶部“运营待办”显示授权范围内严重异常和需接管任务的关注数量。它是定时查询提醒，不是 WebSocket 推送、正式交接签字或自动派单。
- 每类提醒最多显示20项，计数为完整统计；清洁滞留初始阈值是待处理4小时、清洁中2小时，可通过 `stayos.operations.pending-warning` / `cleaning-warning` 修改。页面显示后端返回的实际阈值。
- 房态图和顶部待办在页面可见且最近1分钟有操作时，每30秒重新查询；切回页面时查询。隐藏或闲置时暂停，防止无人操作的电脑因为轮询而一直保持登录。房态超过1分钟未更新会提示过期，正式业务仍由服务器重新校验。

## 2. 身份撤销和退出

入住与退房：预留原幂等标识 → 操作人 `FOR SHARE` → 复查启用、最新角色及当前会话安全版本 → 入住记录/房间/使用段原有锁顺序 → 事务提交。

如果禁用、撤销角色或重置密码先完成，暂停中的业务恢复后拒绝并回滚；如果业务先锁住操作人并合法提交，账号管理等待该事务后完成。保留原24小时幂等行为，失败后可用同一标识合法重试。

CSRF 获取和退出不依赖数据库账号查询，CSRF 防护仍然执行。退出审计失败时记录固定运维提示并继续撤销本机会话，旧Cookie不能再使用。入住、退房、换房等成功业务审计仍必须和业务共同提交，写入失败就整体回滚。

## 3. 健康检查与安全诊断

- `/api/health`：进程存活检查。
- `/api/health/ready`：实际取得数据库连接并查询；不可用返回503，不返回SQL、账号、密码或连接地址。连接池获取超时3秒，检查SQL超时2秒；JDBC连接/读取/取消连接分别设置3/10/2秒上限，避免网络故障导致无限等待，这些超时不能简单相加当作响应时间承诺。
- 每个响应有服务器生成的 `X-Request-ID`。5xx页面提示附该编号，运维可按编号查日志。日志记录接口模板、方法、状态和受控错误分类，不记录请求正文、URL查询、凭证或异常原文。
- 生产 `prod` 配置提供日志滚动：单文件10MB、最多14天、总量1GB。业务审计仍保存在数据库，未擅自决定其清理期限。
- 浏览器测试关闭当前固定版本Playwright的自动AI页面副本，避免失败时将密码/住客输入框内容复制进错误上下文；断言和测试结果仍保留，trace保持关闭。

检查应用与最近备份：

```powershell
pwsh -NoProfile -File .\scripts\check-operations.ps1 `
  -BaseUrl http://127.0.0.1:8080 `
  -StatusDirectory .\backups\status
```

返回JSON；数据库/应用不可用、最近备份失败、没有成功备份或超过26小时均返回非零退出码。可供外部监控调用，但当前没有短信、邮件、值班平台或磁盘容量告警部署，不能把脚本当作已运行的告警服务。

## 4. 生产数据库账号分离

当前开发库账号不变。真实部署由数据库管理员建立一个**新的**运行角色，例如：

```powershell
.\scripts\create-runtime-db-role.ps1 `
  -Container stayos-postgres-1 -Database stayos -RuntimeRole stayos_app
```

脚本隐藏读取20—128字符独立密码，通过stdin传给psql，不写入SQL文件、命令行或输出。目标角色已存在时拒绝覆盖。整个创建及授权为一个事务，已有房间、账号和业务数据不变。

授权依据 `deploy/runtime-grants.sql`：允许必要查询、业务插入、当前状态更新以及账号角色关联删除；不授予DDL、超级用户、创建库/角色、删除业务历史或改写审计/历史表的权限。后续迁移新增表时，由数据库管理员复核后补授必要权限，不自动授予所有新表权限。

私有生产配置需要分别提供：

```text
STAYOS_RUNTIME_DB_USER
STAYOS_RUNTIME_DB_PASSWORD
STAYOS_MIGRATION_DB_USER
STAYOS_MIGRATION_DB_PASSWORD
STAYOS_GUEST_KEY_FINGERPRINT
```

使用 `prod` 时，Spring数据源采用运行账号，Flyway采用迁移账号。生产启动会拒绝运行账号拥有超级用户、建库/建角色、复制、绕过行安全、public建表或改写审计权限的情况。受限账号不改变五种应用岗位角色。

这是已提供的部署能力；本次第五批中受限运行账号与业务权限验收通过，并纳入整版本地完整回归。本次没有给现有开发库降权，也没有进行真实HTTPS生产部署。

## 5. 密钥指纹与原密钥保留

```powershell
.\scripts\show-guest-key-fingerprint.ps1
```

仅输出当前私有配置中原密钥的SHA256指纹，不输出密钥。将该指纹独立记录并在生产配置中固定为 `STAYOS_GUEST_KEY_FINGERPRINT`；prod禁止缺失/空指纹。格式正确但密钥不匹配时，应用拒绝启动。

指纹是原密钥字节的SHA256，不是密钥，不能用于解密，也不替代密钥的独立安全保管。`v1` 是当前密文格式标识，不是密钥指纹；没有更改AES-GCM密文格式或既有幂等HMAC，也没有执行密钥轮换、重新加密或删除旧密钥。

恢复主流程显式提供 `-ExpectedGuestKeyFingerprint`，不匹配或旧归档未保存指纹时拒绝；操作示例见 [BACKUP-RECOVERY.md](BACKUP-RECOVERY.md)。不传该参数的旧隔离恢复调用仍兼容，但未做严格密钥指纹校验，不能宣称已确认密钥身份；指纹比对不代替恢复后的原密钥解密验证，也不能仅凭SHA256清单宣称归档具有防篡改签名。归档不含原密钥，现有工具不支持生产覆盖恢复。

## 6. 可计划执行的备份

先手动验证一次：

```powershell
pwsh -NoProfile -File .\scripts\run-backup-job.ps1 `
  -Container stayos-postgres-1 -Database stayos `
  -OutputDirectory .\backups\archives -StatusDirectory .\backups\status `
  -KeyEnvPath .\.env
```

`KeyEnvPath` 指向所选数据库原住客加密密钥的私有配置，`StatusDirectory` 保存运行状态。每次独立归档并保存密钥指纹、长度和SHA256；保留现有归档及最后成功信息。`last-attempt.json` 表示最近一次结果，`last-success.json` 保留最后成功时间。失败返回非零退出码，不以旧成功结果冒充新任务成功。此包装脚本不是已部署的定时任务。

先预览定时任务：

```powershell
.\scripts\install-backup-task.ps1 `
  -Container stayos-postgres-1 -Database stayos `
  -OutputDirectory .\backups\archives -StatusDirectory .\backups\status `
  -KeyEnvPath .\.env -At '03:00' -WhatIf
```

确认目录、磁盘空间、Docker与权限后，手动去掉 `-WhatIf` 才会注册；拒绝覆盖同名任务，不存Windows密码。任务仅在当前Windows用户已登录且Docker可用时运行，错过触发时间可补运行，同一任务不重叠执行。这不是无人登录服务器的值守方案。

本机目录不是离机备份。目前没有用户指定的离机位置，因此没有安装实际任务或复制真实数据到外部位置。归档仍需受控加密介质、独立密钥、离机副本、外部告警及责任人。尚未设置自动删除/保留周期、WAL时间点恢复、密钥轮换或真实异机切换。

## 7. 可信代理与登录限流

默认 `STAYOS_TRUSTED_PROXIES` 为空，忽略所有转发IP头，客户端不能伪造IP绕过限流。经过可信反向代理部署时，仅配置实际代理的IP/CIDR，例如本机代理为 `127.0.0.1/32`。

代理必须正确覆盖或追加真实来源，禁止信任所有公网地址。后端从右向左核验代理链，使用最近的不可信来源；非法或过长头退回直连来源。该解析只影响登录限流，不擅自改变Host、协议、Cookie或CSRF判断。

仍需在真实代理/HTTPS环境验收来源地址、Cookie Secure、证书及网络访问范围；本次没有部署代理或更改现有本机限流设置。
