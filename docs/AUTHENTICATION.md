# 第 1 阶段：认证与角色权限

本文件记录用户最新开发任务的实现约定。第 1 阶段仅实现认证、固定角色、基础工作区及账号基础管理，不实现酒店业务。此前 DEVELOPMENT 中的阶段编号为旧计划；本次按 1.1 数据库、1.2 后端、1.3 前端、1.4 联调顺序执行。

## 已确认的决定

- 首个管理员：使用一次性终端初始化命令，隐藏输入密码，不接受命令行明文密码；数据库已有管理员（包括禁用管理员）后拒绝再次初始化。两次并发初始化由数据库事务锁保证仅一次成功。
- 五种角色编码统一为 `ADMIN`、`HOTEL_MANAGER`、`FRONT_DESK`、`HOUSEKEEPING_MANAGER`、`HOUSEKEEPING_STAFF`，替代旧草案中的客房角色编码。
- 采用 Spring Security 的服务器 Session + Cookie。用户已在开发任务中授权选择成熟认证方案；无需额外引入 JWT、Redis 或微服务。
- 用户可拥有多个角色，权限取并集。总经理拥有前台、客房执行和客房管理权限，不继承管理员；管理员需要业务功能时追加业务角色。
- 角色与权限映射统一在后端维护，本阶段不提供自定义角色或权限编辑器。数据库只保存角色及用户关联，不为固定权限建立多余配置表。

## 认证如何工作

Session 可以理解为服务器保存的一张登录登记卡。浏览器只持有不可读的随机 Cookie，后端根据它查到登录身份。密码只在登录时校验，不存进 Cookie，也不写入 localStorage。此方案适合当前单体 Web 管理系统，退出时可立即撤销登记卡。

- Cookie：`STAYOS_SESSION`，HttpOnly，SameSite=Strict，仅 Cookie 传递，不允许 URL 携带 Session。
- 本地 HTTP 允许非 Secure Cookie；正式 HTTPS 必须设置 `STAYOS_COOKIE_SECURE=true`。
- 空闲 30 分钟失效；服务重启后登录失效。本阶段 Session 在单个后端进程内保存，不宣称支持多实例共享登录。
- 登录成功更新 Session ID，防止沿用别人事先准备的会话编号。
- CSRF：保留 Spring Security 的默认保护。浏览器先获取与当前 Session 关联的 CSRF token；POST 等修改请求须携带请求头。CSRF token 只是防止其他网站冒用浏览器发请求的校验值，不是登录凭据。登录、退出后重新获取。
- 每次请求重新校验账号状态、账号安全版本及角色权限。账号禁用、密码重置、角色变化会更新安全版本，使旧会话在下一次访问时失效。
- 不启用任意跨域请求；开发前端通过 Vite 代理 `/api`，正式部署应将前后端放在同一站点并启用 HTTPS。

上述机制参考 [Spring Security Session 文档](https://docs.spring.io/spring-security/reference/servlet/authentication/session-management.html) 和 [CSRF 文档](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)。

## 数据与安全边界

- `users`：账号、BCrypt 密码哈希、启用状态、安全版本、连续登录失败次数和临时锁定时间。
- `roles`：初始化五个固定角色，不初始化通用管理员密码。
- `user_roles`：用户与角色的多对多关联；组合主键防重复，外键防止关联不存在的用户或角色。
- `audit_logs`：认证与账号管理的关键操作摘要，只记录内部编号、动作和结果，不保存提交密码、Cookie、CSRF token。
- 用户名统一小写，3—100 位，仅字母、数字、下划线、点、短横线，首位为字母或数字；登录时自动去除首尾空格并转为小写。
- 新密码至少 12 个字符且 UTF-8 编码不超过 72 字节，使用 BCrypt cost=12。数据库额外拒绝不符合 BCrypt 格式的值；格式约束不能代替应用正确计算哈希。
- 账号连续错误 5 次锁定 15 分钟；不存在、禁用、锁定或密码错误统一返回“账号或密码错误，或账号暂不可用”，不透露账号存在与否。
- 额外按连接来源 IP 限制每分钟 60 次登录尝试，超出返回 429。本地单实例内存限流，重启清空；账号锁定保存在 PostgreSQL。默认不信任外部 `X-Forwarded-For`，部署到反向代理后需单独配置可信代理和入口限流。
- 后端工作区接口只返回权限校验结果和基础说明，不提前实现入住或清洁业务。

## 验证顺序

1.1 在独立 PostgreSQL 测试库验证迁移可重复运行、五角色、用户名唯一、关联完整性及拒绝明文密码格式。

1.2 验证登录、统一错误、账号禁用、角色矩阵、多角色并集、CSRF、退出、会话失效、暴力尝试限制及初始化保护。

1.3 验证 TypeScript 检查、生产构建及基础页面。

1.4 使用真实后端与数据库进行浏览器联调，验证五角色导航和越权防护。测试结果以实际执行记录为准。
