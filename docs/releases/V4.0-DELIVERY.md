## 0. 供应商条件核实（如实记录）

截至本版实施时，用户未指定首个真实供应商，也不存在接口权限、正式供应商文档或沙箱/测试账号。按第 14 节"缺少条件时可完成 adapter 协议、持久化和可控模拟测试"的回退路径执行：

- 完成供应商无关核心（6 表、入站/发件箱/对账、有序领取、有界重试、人工处理）。
- 完成 adapter SPI（签名验证/解析/推送/快照）与受控模拟供应商 `SIMULATOR`（HMAC-SHA256 签名回调 + 内存台账回显推送，不猜测任何真实厂商私有接口）。
- 真实供应商状态保持 **`BLOCKED_EXTERNAL`**；本版**不宣称**与任何真实渠道的端到端集成通过。接入真实供应商时需用户指定 + 合法接口权限 + 正式文档 + 沙箱账号 + 房型/价格映射与回调认证方式，再扩展 `supplier_code` CHECK 与对应 adapter。

## 1. 交付范围

### 数据（V19，已冻结）

`V19__channel_integration.sql` 6 表：`channel_connections`（凭据只存引用、BLOCKED_EXTERNAL 状态、乐观锁 version）、`channel_mappings`（编码↔房型/价格计划双唯一）、`inbound_events`（(connection, external_event_id) 唯一、序号协议、PENDING 部分索引）、`outbox_events`（7 类事件、SENT/sent_at 一致性 CHECK）、`sync_attempts`（追加只写流水）、`reconciliation_runs`（RUNNING/finished_at 一致性 CHECK、差异 JSONB）。`deploy/runtime-grants.sql` 同步（sync_attempts 不授予 UPDATE/DELETE）。

### 后端（com.stayos.integration）

- `SupplierAdapter` SPI：verifyCallback / parseCallback / push / snapshot；厂商字段止步于 adapter，不进核心 DTO。
- `SimulatorAdapter`：受控模拟供应商——HMAC-SHA256（`X-StayOS-Signature`，常量时间比较）、中性 StandardInbound 解析、推送回显内存台账、快照读台账。
- `CredentialResolver`：引用 → 系统属性 → 环境变量 → Spring Environment；不可解析即 409 `CREDENTIAL_UNRESOLVED`；密钥值不入库、不进日志/接口/审计。
- `ChannelService`：入站"先持久化后处理"，签名失败 401 不落任何内容、重复 409 `DUPLICATE_EVENT`、乱序记 `OBSOLETE` 事实；`ORDER_CREATE/MODIFY/CANCEL` 全部经共享 `ReservationService`（幂等键为事件身份派生的确定性 UUID；拒绝跨渠道操作）；失败退避 attempts²×2s（上限 600s）、`MAX_ATTEMPTS=8` 转 `MANUAL`；出站按 id 有序领取、`PAUSED/BLOCKED_EXTERNAL` 跳过、推送在业务事务外；对账按外部单号比对本地/远端并落差异明细。
- `ChannelOutboxRecorder`：以 `@Transactional(MANDATORY)` 加入调用方事务——预订确认/修改/取消/入住与库存停售/恢复与 outbox 同一本地事务；无渠道出身的柜台操作不入队。
- `ChannelOutboxWorker`：每 5s 数据库有序领取（`for update skip locked`、短事务）。
- `ChannelController` / `CallbackController`：`/api/channels*` 全部 `channel:manage`（仅总经理）；回调路径免登录但受签名保护，CSRF 仅对 `POST /api/integration/callbacks/{supplierCode}` 精确豁免（全局 CSRF 不关闭）。
- 预订服务/库存服务出站钩子 + `AuditQuery` CHANNEL 模块 9 动作 + `RolePermissions`、`SecurityConfig`、`@EnableScheduling` 接线。

### 前端

- `/channels` 渠道连接页（总经理）：连接列表（状态、待处理/人工计数、最近收发/错误）、新建/编辑连接（凭据仅引用名并即时校验解析）、暂停/恢复、映射维护（含本地对象选择）、入站/出站事件页签（状态筛选、`MANUAL` 重新入队）、立即处理、立即对账与对账记录页签。
- 路由 `meta.permission=channel:manage`；侧边导航 22 渠道连接（权限可见性）；侧栏版本 StayOS V4.0；操作记录新增 CHANNEL 模块与 9 动作中文名；运营页快捷入口。

## 2. 关键实现事实与实测修复

- 入站回放幂等键：幂等表要求 UUID，直接拼 `ch-{conn}-{event}` 会被拒（实测 `请提供有效的业务请求标识`）→ 改为事件身份派生 `UUID.nameUUIDFromBytes`，同一事件重放/重试键稳定。
- 出站事件去重：`modify()/cancel()/confirm()` 内部钩子按入站关联定位连接入队；`ORDER_CREATE` 因 `result_reservation_id` 尚未落库（事件事务后才 finish），由 applyInbound 显式补 `RESERVATION_CONFIRMED`，MODIFY/CANCEL 交由服务钩子避免重复入队。
- 柜台操作回归修复：`recordReservationEvent` 用 `queryForList` 空集返回 null（原 `queryForObject` 会让无渠道出身的确认/修改/取消直接 500）。
- MyBatis：动态 SQL `<if>` 必须 `<script>` 包裹（claim 两查询补齐）；JSONB 边界统一"字符串进、`::text` 出"（`JsonNode` 直接绑定 PG jsonb 失败，实测 TypeException）。
- `channel_connections` 补 `version` 乐观锁列（迁移冻结前修正，测试库重放）。
- 审计补齐：连接/映射四个写动作补 `audit.success`（原仅失败与重试/处理/对账有审计，浏览器验收暴露）。
- 测试清理顺序实测修正：idempotency→渠道表→预订（inbound_events.result_reservation_id 先于 reservations 删除）→房间/类型→用户。
