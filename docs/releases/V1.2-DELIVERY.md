## 实现范围

入住详情 → 本次实际住客 → 更正住客资料。仅前台/总经理 `stay:guest-correct`，仅在住登记笔误；姓名、证件类型/号码和电话可按字段选择更正，主要联系人和同住名单不变。未提交字段保留，明确空电话清空，null 不接受。敏感输入从空字段重填，关闭/成功清除。

沿用 Java 21 / Spring Boot / MyBatis / PostgreSQL / Flyway / Vue / Element Plus；同一工作台、绿色主题和手机适配，不增加依赖。V14 增加 guests.version、登记快照唯一关联、只追加 guest_corrections 及幂等指针。完整前后四字段快照采用现有 AES-GCM、专用 guest-correction AAD 和随机 IV；现有 document/phone 密文格式保留。普通历史、回执只返回脱敏前后值与字段名。

幂等预留 → 操作人及会话复核 → 入住锁 → 按 guest ID 排序加锁。更正与退房/换房串行，住客版本防止覆盖。当前投影、历史、成功审计 GUEST_CORRECT 与幂等回执同事务；失败全部回滚。当前入住版本、占用、使用段、同住关联与清洁任务不因更正变化。

运行角色只获 guests 必要七列 UPDATE 和 guest_corrections INSERT；更正历史不可 UPDATE/DELETE，不能改密钥标识/备注。升级遇到异常跨登记共享快照时拒绝迁移，需先核查数据来源，不静默复制或改写历史。

## 接口和失败恢复

契约详见 [API.md](../API.md) V1.2。POST `/api/stays/{stayId}/guests/{guestId}/corrections` 输入 `{version,changes,reason}` + UUID key；同路径 GET 分页历史。GET `/api/stays/guest-corrections/result/{key}` 只查当前操作人的成功回执，过期成功仍可查。无原号码明文读取或导出接口。

浏览器仅 sessionStorage 保存 UUID，敏感 payload 只用于当前打开表单内的原 key 重试；关闭即清除，重开/刷新只查回执。未知结果不自动新 key 重发，404 不代表原操作失败。总经理集中操作记录支持“住客资料更正”筛选。
