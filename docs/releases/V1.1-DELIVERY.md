## 固定契约

- 仅 `stay:manage`（前台/总经理），仅在住记录；允许延长或缩短计划，新的预计离店时间须晚于服务器当前时刻和实际入住时刻、且不同于原值。原因必填、最多 1000 字，不填写敏感住客信息。
- `POST /api/stays/{id}/extensions`：`{segmentId,version,newExpectedCheckOutAt,reason}` + `Idempotency-Key`。返回不可变操作回执，字段为 `id,stayRecordId,segmentId,roomNumber,oldExpectedCheckOutAt,newExpectedCheckOutAt,reason,operatorId,operatorName,operatedAt,stayVersion`。
- `GET /api/stays/{id}/extensions?page=1&pageSize=20` 返回标准分页；`GET /api/stays/extensions/result/{key}` 仅查询当前操作人自己的成功回执。后者用于丢失响应或刷新恢复，不返回原始敏感请求。
- V13 增加入住 `version`、`stay_extensions` 历史、幂等结果引用与操作类型；续住/退房/换房均增加入住版本。原退房/换房请求参数兼容。
- 续住锁顺序：幂等预留 → 操作人共享锁/会话安全版本 → 入住 → 当前房间 → 当前使用段。旧版本/旧使用段返回 409，成功事实与审计共同提交。
- 前端只保存无正文的请求 key；刷新后查询结果，不自动重发。原 payload 仅留内存用于同 key 重试，关闭后清除普通表单敏感内容。
- 时间输入明确北京时间；API 使用带偏移 ISO 时间，规范化为 UTC 微秒精度匹配 PostgreSQL。服务端时间为最终依据。
- 不收费，不新建入住、不结束使用段、不创建任务；不开发 V1.2 或更后版本。
