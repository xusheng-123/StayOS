## 1. 交付范围

### 数据（V20，已冻结）

`V20__customer_profiles.sql` 2 表 + 幂等扩展（详见 docs/DATABASE.md V5.0 节）：`customer_profiles`（证件/电话 AES-GCM 密文 + 掩码，状态 ACTIVE/DISABLED/MERGED，合并终态与不可删除由两个触发器在数据库层兜底，乐观锁 version 从 1 起）；`customer_profile_stays`（`guest_id` 唯一——每次登记的住客快照最多属于一个档案，"另一档案抢挂"在数据库层不可能）。档案与入住登记快照（`guests`/`stay_guests`）完全分离：关联是引用不是复制，解除关联不碰任何历史。

### 后端（com.stayos.customer）

- `CustomerProfileService`：建档/编辑/停用恢复/合并/关联/解除关联。写操作全部走共享 `IdempotencyService`（新增 PROFILE 结果种类、6 个 CUSTOMER_PROFILE_* 操作），幂等预约与业务提交同事务；建档字段校验复用 `GuestValidation.require`（与入住登记同一套姓名/证件/电话规则，`public` 化，无第二套规则）。
- 同名提示而非自动身份：建档响应携带 `similarActiveProfiles`（同名启用档案，最多 5 条），仅提示人工核对；系统不因同名/共用手机号自动合并、自动关联。
- 受控合并：仅 `customer:merge`（总经理）；目标必须 ACTIVE；合并 = 源档案置 MERGED + 关联行整体移交目标；源档案从此终态（编辑/状态/再合并全部 409 `PROFILE_MERGED`）；错误合并的修正路径是"解除关联 + 重新关联"，不提供任何"取消合并"或删行能力。
- 访问留痕：档案详情每次访问审计 `CUSTOMER_PROFILE_VIEW`；7 个动作全部 `audit.success` 落操作记录（审计模块 CUSTOMER）。
- 加密边界：`GuestProtection.encrypt/mask`（KEY_ID v1）；响应与列表只含掩码（如 `+8****00`/`11****34`），解密方法保持 package-private，任何接口不返回明文。
- 权限接线：`RolePermissions` FRONT_DESK/HOTEL_MANAGER += `customer:read`/`customer:manage`，HOTEL_MANAGER += `customer:merge`；`SecurityConfig` 增加 `/api/customer-profiles/**` URL 白名单（否则 `anyRequest().denyAll()` 全拒）。
- 集成实测修复（均为产品代码修复，非仅测试绕过）：SecurityConfig 漏配 URL 导致 403；IdempotencyService 结果种类 switch 漏 PROFILE 导致重放 409 REQUEST_IN_PROGRESS；Mapper 注解 SQL 中 HTML 实体（`&lt;&gt;`）只在 `<script>` 内生效、普通注解 SQL 必须字面 `<>`；可空绑定参数需 `CAST(#{p} AS bigint)`；`mergedInto` 查询列数与 MergedTarget 构造器不匹配导致合并 500；V20 `version` 列默认值 0 与 `@Positive` 契约矛盾 → 冻结前改为 `DEFAULT 1 CHECK (version>=1)` 并重放测试库。

### 前端

- `/customers` 客历档案页：筛选（姓名/状态）、列表（掩码列）、详情面板（合并提示告警、同名核对引导、档案事实、关联入住表）、新建/编辑对话框（编辑不回显证件/电话，从空重填）、停用恢复、关联入住（按住客姓名检索真实入住）、解除关联、合并对话框（候选人选择 + `ElMessageBox` 人工确认）。
- 合并入口按 `can('customer:merge')` 控制；路由 `meta.permission=customer:read`；侧边导航 23 客历档案（权限可见性）；侧栏版本 StayOS V5.0；操作记录新增"客历档案"模块与 7 动作中文名；运营页快捷入口。

## 3. 已知边界（不隐瞒）

- 本版不做：批量导出、营销能力、会员/积分/储值、协议单位（权限未定义即不存在；手册第 16 节明确后置）。
- 客历"证件号查重"不做自动匹配：同名提示只按姓名；跨档案同证件号的提示与人工合并辅助属于后续候选（需要时先定义权限与审计）。
- 证件/电话保持加密与掩码；敏感输入不入日志/URL/审计文本；账务表不复制住客身份资料（沿袭既有红线）。
- 过程记录：本轮 VERIFY 期间一次全量回归被我主动中断（发现 OperationsInfrastructureTest 迁移计数断言需随 V20 更新），该中断使上一轮的 BootstrapTest 清理未执行、测试库遗留一个启用管理员，导致紧接的重启轮次中 AuthIntegrationTest 末位管理员保护断言失败一次；重置测试库后干净重跑全绿。属实施过程状态污染，非产品缺陷，两次结果均如实记录于此。
