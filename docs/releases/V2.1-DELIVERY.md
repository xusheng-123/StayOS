## 2. 已做（对应手册第 12 节）

### 数据与基础设施（V17）

- 新表 5 张：
  - `business_days`：显式营业日登记表，行随业务惰性创建并固定当时的生效政策（`policy_id`），即使之后政策改版，该日的事件归日口径以存储的政策日切为准；`CLOSED` 不可重开（触发器拒绝）。
  - `cashier_shifts`：收银班次 `OPEN → SUBMITTED → CONFIRMED` 单向状态机（触发器白名单，CONFIRMED 不可变）；期初备用金非负、期末实盘非负、状态与时间戳字段一致性 CHECK；偏导唯一索引保证**一个收银员同时只有一个 OPEN 班次**。与 V1.3 `shift_handovers`（非财务事项交班）完全独立。
  - `cash_counts`：提交班次时写入的不可变实盘记录，`difference = counted − expected` 由 CHECK 固化，差异非零必须带原因；表级只追加（UPDATE/DELETE 拒绝）。
  - `daily_close_runs`：人工关账批次，`RUNNING → COMPLETED/FAILED`；偏导唯一索引 `uq_daily_close_running` 保证**每个营业日同时只有一个 RUNNING 批次**（数据库锁，不依赖 JVM 静态锁）；进度列 `steps_done 0-4`、失败原因留痕，终态不可变、不可删除。
  - `daily_reports`：关账成功时固化的 JSONB 快照，一营业日一份（UNIQUE），只追加。
- `payment_records` 增加 `cashier_shift_id`（收款入账时点按收款人的 OPEN 班次归属，事后不回改；索引带 `WHERE cashier_shift_id IS NOT NULL`）。
- 幂等扩展：`idempotency_requests` 增加 `result_cashier_shift_id` 与 `CASHIER_SHIFT_OPEN/SUBMIT/CONFIRM` 三个操作；结果列互斥 CHECK 以子串包裹方式扩展（沿用 V15/V16 模式）。
- `deploy/runtime-grants.sql`：受限运行角色补 5 张新表 INSERT 与 `business_days/cashier_shifts/daily_close_runs` UPDATE；`cash_counts/daily_reports` 仍无 UPDATE/DELETE。
- `SecurityConfig` 显式放行 `/api/cashier-shifts/**`、`/api/business-days/**`、`/api/reports/**`。
- 权限：`cashier:operate`（FRONT_DESK、HOTEL_MANAGER）；`cashier:close`、`report:finance`（仅 HOTEL_MANAGER）；客房岗位与 ADMIN 无收银权限、看不到金额。审计模块表加入 CASHIER（4 个动作）。
- `BusinessActorGuard` 新增 `hasPermission`：无锁布尔探测，用于"本人/全部"等或然分支（不替代事务内的 `require`）。

### 后端（`com.stayos.cashier`，5 个类）

- `CashierController`：9 个端点 — `GET/POST /api/cashier-shifts`、`GET /api/cashier-shifts/{id}`、`POST /{id}/submit`、`POST /{id}/confirm`、`GET /api/business-days`、`POST /api/business-days/{date}/close`、`GET /api/reports/daily`。方法级 `@PreAuthorize`：班次查询/开启/提交与营业日查询/关账入口为 `cashier:operate`，确认与关账为 `cashier:close`，日报为 `report:finance`。
- `CashierShiftService`：
  - 开班（幂等 `CASHIER_SHIFT_OPEN`）：先预约幂等再 `require` 权限；已有 OPEN 班次 → `SHIFT_ALREADY_OPEN`；当日营业日行缺失且无生效政策 → `BILLING_POLICY_REQUIRED`。
  - 提交（幂等 `CASHIER_SHIFT_SUBMIT`）：`SELECT ... FOR UPDATE OF cs` 行锁班次；只能提交本人班次；账面应存 = 备用金 + 实收现金 − 退款现金；差异非零必须填原因（只入 `cash_counts`，**不回改任何已入账收款**）；版本不符 → `STALE_VERSION`。
  - 确认（幂等 `CASHIER_SHIFT_CONFIRM`）：仅 `cashier:close`，仅 SUBMITTED 可确认，一次性。
  - 前台只看本人班次；`scope=all` 与跨人详情需要 `cashier:close`。
- `BusinessDayService`：关账为三段显式事务（`TransactionTemplate`，因自调用不走代理）：
  1. 预约：事务内 `require cashier:close` → 确保营业日行 → 已关账 → `DAY_ALREADY_CLOSED` → 插入 RUNNING 批次（并发第二个 → 数据库唯一索引 → `DATA_CONFLICT`）；
  2. 工作：① `VERIFY_ROOM_FEES` 逐段核对房费（未开立客账/缺少房费/日价不符，逐条具名报错）；② `RECONCILE` 汇总费用与资金（同口径查询，固化于同一事务）；③ `REPORT_FROZEN` 写 JSONB 快照（费用/资金/出租分母/数据不足标记/当期调整追溯/口径说明）；④ `DAY_CLOSED` 标记 CLOSED + 批次 COMPLETED；失败步骤回滚，进度经独立事务保留。
  3. 失败标记：工作事务异常时在新事务写 FAILED 原因（截断 1000），营业日保持 OPEN 可重试，重试从头全量复核。
  - 金额口径：费用按 `folio_charges.business_date`，资金按政策日切归日（凌晨 00:00-04:00 收退归前一营业日）；出租分母 = 启用房 − 维修停售覆盖日，无可售房或无已售房晚时出租率/ADR 显式 `null` 并写入"数据不足"，不伪造。
- `CashierDtos`：金额十进制字符串（`[0-9]{1,8}(\.[0-9]{1,2})?`，上限 99999999.99）；营业日按 Asia/Shanghai。
- 幂等接点：`IdempotencyService` 补 `reserveCashier/completeCashierShift`（`Propagation.MANDATORY`，事务内调用）；`StayMapper.RequestResult` 补结果列。
- `ApiErrors`：沿用既有映射，新增约束冲突自然落入通用 409 `DATA_CONFLICT`；未预期异常现在带完整堆栈记录（`log.error(..., failure)`），问题编号仍只回传类目。

### 修复与实测发现

- 关账进度触发器过严：`validate_daily_close_run_update` 初版把 `RUNNING→RUNNING` 的进度更新一并拒绝，导致关账工作事务必然失败（409 DATA_CONFLICT）；改为仅拒绝终态行改动与携带终止字段的进度更新，`RUNNING→COMPLETED/FAILED` 单向不变。
- `CountRow` 缺 `id` 字段：`@Options(useGeneratedKeys)` 找不到 keyProperty setter 抛 ExecutorException（INTERNAL_ERROR）；补字段。
- JSONB 快照读取：JDBC 返回 `PGobject` 而非 Map、`created_at` 返回 `java.sql.Timestamp`，日报接口先后两次 ClassCastException；统一归一化（快照字符串按 `USE_BIG_DECIMAL_FOR_FLOATS` 解析保留金额刻度）。
- e2e 金额断言修正：快照数字为 JSON number，测试端 Jackson 默认按 Double 解析丢刻度（288.00 → "288.0"）；改为 `decimalValue()` 数值比较（与响应本身无关）。
- e2e 连续 prompt 的严格模式冲突：前一个 MessageBox 卸载动画未结束时 `.el-message-box` 同时匹配两个；按标题过滤定位。
- 审计可见范围遗漏：CASHIER 模块注册了 4 个动作但未加入 `audit:business` 覆盖清单，总经理在操作记录页看不到收银审计；补入 `AuditQuery.scope`。

## 4. 边界与遗留

- 首版不提供重开已关账日；当期调整记在当前营业日并在日报 `laterAdjustments` 留痕。
- 关账后不改原日报；首版报表不含 RevPAR（手册未要求），ADR/出租率分母不可靠时显式"数据不足"。
- 不接真实自动支付；普通收据不标为法定发票；收银与日报页面不展示住客证件、电话。
