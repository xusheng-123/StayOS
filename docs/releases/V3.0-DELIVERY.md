- 版本：V3.0（手册第 13 节）
- 状态：VERIFIED_LOCAL（本地验收通过，未部署）
- 完成日期：2026-11-01

## 1. 交付范围与冻结契约

按手册第 13 节实现"一单一房可多晚"的预订与未来库存，全部阶段走完 DISCOVER → CONTRACT → DATA → BACKEND → FRONTEND → INTEGRATE → VERIFY → HANDOFF。

### 1.1 状态机与区间

- 预订状态：`HELD → CONFIRMED → CHECKED_IN`，旁路 `CANCELLED`、`NO_SHOW`；迁移白名单由数据库触发器 `validate_reservation_update` 强制，CONFIRMED/CANCELLED 等终态字段一致性 CHECK。
- 入住区间：`[arrivalDate, departureDate)` 半开区间，至少一晚，最长 365 晚；到店日不得早于当前营业日。
- 保留单：默认到期时间 `now + 24 小时`，可显式指定；到期由 `POST /api/reservations/release-expired` 扫描释放（`for update` 锁批 200，天然幂等），取消原因固定"保留单到期自动释放"。
- 来源：`PHONE / WALK_IN / OTA / OTHER`；外部单号选填、去重（`EXTERNAL_REF_EXISTS`），最长 120 字。
- 联系电话：可选；有值时 GuestProtection AES-GCM 加密保存（`v1.` 前缀密文 + 掩码 + key id），无值时掩码存空串；接口与页面只出现掩码（如 `13****34`），无解密读取口。

### 1.2 库存与并发

- 计数表 `inventory_days(room_type_id, stay_date, sold)`：`INSERT … ON CONFLICT DO NOTHING` 保证锁行可靠存在，再按 `(room_type_id, stay_date)` 升序 `SELECT … FOR UPDATE` 锁定，行数校验后才占用/释放；`sold CHECK >= 0` 让重复释放以约束失败暴露（映射 409）。
- 可售公式（每夜）：`blocked>0 ? 0 : enabled_rooms − occupied − sold`；`occupied` 按"营业日夜晚"统计在住段（`[入住日, 实际/预计离店日)`，正午退房不会溢出到次夜），与预订区间同一半开口径；`sold` 只统计 HELD/CONFIRMED 预订。
- 默认禁止超卖：占满夜晚的创建/修改以 `ROOM_TYPE_SOLD_OUT` 具名拒绝（报出首个满夜日期）。
- 转入住不双扣：预订转入住先释放 `sold`，占用转移到在住段，同一夜晚绝不双向计数；提前离店允许，释放的夜晚回到可售。
- 修改（日期/房型）同一事务内先锁旧+新日期（房型 id、日期升序）→ 释放旧 → 核验新 → 占用新 → 版本乐观锁更新；任一步失败整体回滚，原预订与原库存保持不变。跨房型按房型 id 升序加锁，避免死锁。
- 续住/换房与未来库存衔接：`StayExtensionService` 与 `RoomChangeService` 在既有校验后新增只读的未来库存冲突提示（`FUTURE_NIGHT_CONFLICT`），只提示不自动赶客；预订侧转入住对超期做同一具名冲突校验。实际超期未退仍以运营待办提醒，不自动结束住。
- 停售：`inventory_blocks` 为房型级计划停售 `[startDate, endDate)`，区间内可售归零，不影响在住客人与既有事实；解除后恢复。DIRTY 房态不等于未来永久停售。

### 1.3 订金（复用 V2 真实资金记录）

- 收订金：`POST /api/reservations/{id}/deposits`，写入 `payment_records`（`folio_id` 空 + `reservation_id`，purpose=DEPOSIT，currency CNY），归属收款人进行中收银班次；权限 `billing:receive`。
- 退订金：`POST /api/reservations/{id}/deposits/refund`，权限 `billing:refund`（仅总经理）；不超原笔未退金额与订金余额（`REFUND_EXCEEDS_LIMIT`）；REFUND 行 purpose 为空（schema CHECK），refund_of 关联原收款。
- 迁移不重复计收：开立客账时（`FolioService.open`）把该预订未关联客账的订金 UPDATE 挂到 folio（保留 reservation_id 双关联以便追溯），守卫触发器 `guard_payment_record_migration` 只放行这一种 UPDATE 且其余字段全等；客账汇总中订金只出现一次。
- 取消罚金：首版未配置罚金政策，罚金固定 0.00 元并在事件/文档如实记录。

### 1.4 幂等与权限

- 12 个新幂等操作（RESERVATION_CREATE/MODIFY/CONFIRM/CANCEL/NO_SHOW/ASSIGN_ROOM/CHECK_IN/EXPIRE_RELEASE/DEPOSIT_RECEIVE/DEPOSIT_REFUND、INVENTORY_BLOCK_CREATE/RELEASE）写入 `idempotency_requests`，结果列 `result_reservation_id`/`result_inventory_block_id`（互斥 CHECK 扩展）。canonical 输入取原始请求字段（heldUntil 未指定时以空串参与哈希），同键同内容回放返回首次结果，不同内容报 `IDEMPOTENCY_MISMATCH`。
- 权限：`reservation:manage`（前台、总经理），`inventory:manage`（仅总经理）；预订退款另需 `billing:refund`（仅总经理）。`/api/reservations/**`、`/api/availability`、`/api/inventory/**` 显式放行认证。
- 审计：RESERVATION 模块 12 个动作进入 `audit:business` 覆盖；事件表 `reservation_events` 只追加（触发器强制）。

## 4. 前端（详见页面）

- `/reservations`：状态/日期/关键字筛选、新建预订对话框（区间、房型、来源、外部单号、联系人、电话、备注）、释放到期保留单。
- `/reservations/:id`：全字段详情、确认/修改/取消/未到店/分房/转入住按状态出按钮、订金收退（退款仅总经理可见）、事件轨迹；转入住成功后跳转入住详情。

## 6. 已知边界与后续

- 续住/换房的未来库存冲突检查为只读提示（不锁库存行），与预订操作间存在理论竞态，按手册 §5.4 记录为可接受残余风险；预订↔预订为确定性串行。
- 订金退款权限沿用 V2 的 `billing:refund`（仅总经理）；罚金政策缺失如实记 0。
- 停售是房型级整体停卖，不支持按房间子集停售（手册首版未要求）。
- V2.1 提交 `e8d8df2` 仍在本地，推送远程需用户单独授权；本版 HANDOFF 完成后同样只提交不推送。
