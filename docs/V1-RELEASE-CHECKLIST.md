# StayOS V1.0 试运行准备清单

本清单用于区分开发验收和真实酒店上线。自动化测试通过不代表已经允许处理真实住客资料。第八阶段实际数量、耗时和已知限制以根目录 `PHASE8-DELIVERY.md` 为准。

## 已验证通过

- 前七阶段测试基线：245项JUnit、102项Playwright，失败/错误/跳过均为0。
- 五角色既定业务边界；ADMIN不自动办理入住、退房、换房、分房或执行清洁；分房仍只授予客房主管和总经理；自主领取保持关闭。
- 原有入住、换房、退房、清洁、异常、停用的真实数据库业务流程和事务保护。
- 第八阶段隔离恢复专项演练：真实备份/恢复、21张表内容核对、正确测试密钥解密、错误和缺失密钥拒绝、重启及持久化幂等、隔离数据库故障恢复、超时与提交失败回滚。

最终全项目回归：260项JUnit、121项Playwright通过，失败/错误/跳过均为0；另外1项恢复补充复验通过。前后端构建成功。10并发300次查询和5并发30秒750次查询无意外失败；8类手机视口通过。详见第八阶段报告，不能用本清单替代测试记录。

## 部分完成，需要进一步验证

| 项目 | 当前已有能力 | 尚需落实 |
|---|---|---|
| 审计与历史 | 现有审计事实、岗位范围只读查询、模块业务历史 | 生产日志存储、访问审查、告警、审计保留期限；没有防DBA篡改的独立审计存储 |
| 个人信息保护 | 密码BCrypt、证件/电话AES-GCM、脱敏响应和最小权限 | 真实业务字段必要性、人员授权培训、访问管理、留存政策及完整安全评估 |
| 备份恢复 | 手动PowerShell备份、文件ACL、SHA256、真实隔离恢复 | 离机副本、自动任务和失败告警、生产演练与负责人，确定可接受的数据丢失量和恢复时间 |
| 密钥管理 | Git外环境配置、缺失密钥启动失败、测试密钥恢复验证 | 独立安全保管、授权人员、灾难情况下获取方式、轮换和旧密钥恢复；v1不是唯一密钥指纹 |
| Session/Cookie | HttpOnly、SameSite=Strict、CSRF、禁用账号复查，重启后重新登录 | HTTPS部署下启用Secure、域名和代理配置审查；当前本地HTTP不是生产加密传输 |
| 性能稳定性 | 本地合理规模并发和短时间稳定性检查 | 与生产服务器一致的长时间、容量、磁盘、网络与故障监控测试 |
| 移动端 | Edge模拟常见手机视口 | 实际手机、触屏、不同浏览器、真实弱网和打印/酒店现场设备测试 |
| 应急流程 | 数据库/应用排查与隔离恢复说明 | 指定联系人、离线操作安排、演练频率、通知渠道和恢复后核对责任 |

## 尚未完成

- 真实酒店的实名身份核验、住宿登记及必要的外部系统对接要求确认；本项目没有新增公安身份核验对接。
- 个人信息保留期限、清理/匿名化政策、备份中的个人信息处理规则和操作审批。
- 真实生产部署、HTTPS证书、受限网络、生产数据库账号权限和运维账号管理。
- 生产密钥保管与恢复流程、自动备份/告警、异机灾难恢复及生产容量验收。
- 真机与实际岗位人员现场验收、用户操作培训及正式应急值守安排。

## 当前阻止正式运营的问题

1. 尚未确认真实酒店的身份核验、住宿登记和个人信息处理要求，不能据此收集真实住客数据。
2. 当前HTTP回环地址、开发容器/账号、本地配置和单机内存Session尚未经过生产安全部署验收。
3. 本地恢复成功不能替代离机备份、密钥独立保管、恢复责任人和生产环境灾备演练。
4. 尚未完成生产服务器长时间容量测试、真实设备测试及数据保留/清理政策。

本阶段不进行真实生产部署，不宣布已经满足正式酒店运营要求，也不引入收费、预订、主管验收等额外业务。
